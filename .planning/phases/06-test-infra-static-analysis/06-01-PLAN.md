Per D-09 and D-10, refactor both scripts to support NOTIFY_LOCK_DIR environment variable override:

**notify-play.sh changes:**
Replace line 14:
```
LOCK_FILE="/tmp/claude-notify-${TYPE}.lock"
```
With lines 14-15:
```
LOCK_DIR="${NOTIFY_LOCK_DIR:-/tmp}"
LOCK_FILE="$LOCK_DIR/claude-notify-${TYPE}.lock"
```
This is backward-compatible: when NOTIFY_LOCK_DIR is unset, LOCK_DIR defaults to /tmp, producing the same lock file path.

**notify-play.ps1 changes:**
Replace line 18:
```
$TempDir = if ($env:TEMP) { $env:TEMP } else { [System.IO.Path]::GetTempPath() }
```
With line 18:
```
$LockDir = if ($env:NOTIFY_LOCK_DIR) { $env:NOTIFY_LOCK_DIR } elseif ($env:TEMP) { $env:TEMP } else { [System.IO.Path]::GetTempPath() }
```
And update line 19 to use $LockDir instead of $TempDir:
```
$LockFile = Join-Path $LockDir "claude-notify-$Type.lock"
```

Priority: NOTIFY_LOCK_DIR > $env:TEMP > system temp path. Mirrors bash behavior per D-10.

- Verify `grep "NOTIFY_LOCK_DIR" scripts/notify-play.sh` finds exactly 1 match
- Verify `grep "NOTIFY_LOCK_DIR" scripts/notify-play.ps1` finds exactly 1 match
