    In `test.sh`, modify the `run_bash_tests()` function (lines 71-75).

    The current code is:
    ```bash
    run_bash_tests() {
        echo "=== bats-core tests (Docker) ==="
        docker run --rm -v "$REPO_ROOT:/app" "$BATS_IMAGE" \
            sh -c "apk add --no-cache jq > /dev/null 2>&1 && bats /app/tests/bash"
    }
    ```

    The bats/bats:1.11.0 image has ENTRYPOINT `['/tini', '--', 'bash', 'bats']`. Passing `sh -c "..."` as arguments results in `bash bats sh -c "..."` inside the container, where `sh` is interpreted as a test file path.

    Change it to:
    ```bash
    run_bash_tests() {
        echo "=== bats-core tests (Docker) ==="
        docker run --rm --entrypoint /bin/sh -v "$REPO_ROOT:/app" "$BATS_IMAGE" \
            -c "apk add --no-cache jq > /dev/null 2>&1 && bats /app/tests/bash"
    }
    ```

    The changes:
    1. Add `--entrypoint /bin/sh` before the image name to override the image's ENTRYPOINT
    2. Change `sh -c` to just `-c` since the entrypoint IS /bin/sh now — the `-c` flag is passed directly to `/bin/sh`

    This ensures the command inside the container is exactly `/bin/sh -c "apk add ... && bats ..."`.
