function Invoke-MediaPlayer([string]$AudioFile) {
    Add-Type -AssemblyName PresentationCore
    $player = New-Object System.Windows.Media.MediaPlayer
    $player.Open([System.Uri]::new($AudioFile))
    Start-Sleep -Milliseconds 500
    $player.Play()
    while ($player.NaturalDuration.HasTimeSpan -and $player.Position -lt $player.NaturalDuration.TimeSpan) {
        Start-Sleep -Milliseconds 100
    }
    $player.Close()
}

Wait -- dot-sourcing a param() script with mandatory params will prompt or error. The correct approach for Pester:

The script has `param()` with mandatory params. When dot-sourced, PowerShell tries to bind the params from the calling scope. To avoid this, we need a different strategy.

**Correct strategy per RESEARCH Pitfall 2 and Open Question 1:**

For PS-01 through PS-03, we need to call the script's logic with Mock on Invoke-MediaPlayer. The cleanest approach:

1. Do NOT dot-source the whole script (it has param() that binds awkwardly)
2. Instead, for PS-01~03: Dot-source the script with explicit param values passed as arguments. In PowerShell, `. script.ps1 -Type "complete" -AudioFile "/app/audio/file.mp3"` works but executes the script immediately.
3. The better approach: Define Invoke-MediaPlayer in the test's BeforeAll, then when the dot-sourced script runs and hits `Invoke-MediaPlayer`, the Mock intercepts it.

Actually the cleanest approach following RESEARCH Pattern 2:

```powershell
Describe "notify-play.ps1 cooldown and playback" {
    BeforeEach {
        # Isolate lock directory (per D-02, D-06)
        $TestDir = Join-Path ([System.IO.Path]::GetTempPath()) "pester-notify-$(Get-Random)"
        New-Item -ItemType Directory -Path $TestDir -Force | Out-Null
        $env:NOTIFY_LOCK_DIR = $TestDir
    }

    AfterEach {
        Remove-Item -Path $TestDir -Recurse -Force -ErrorAction SilentlyContinue
        Remove-Item Env:NOTIFY_LOCK_DIR -ErrorAction SilentlyContinue
    }

    It "skips playback when lock file is younger than 5 seconds (PS-01)" {
        # Create recent lock file
        $lockFile = Join-Path $env:NOTIFY_LOCK_DIR "claude-notify-complete.lock"
        Set-Content -Path $lockFile -Value "recent" -NoNewline

        # Define mock BEFORE invoking script
        Mock Invoke-MediaPlayer {}

        # Dot-source with params -- this executes the script in current scope
        # The cooldown check will find the fresh lock file and return before reaching Invoke-MediaPlayer
        . /app/scripts/notify-play.ps1 -Type "complete" -AudioFile "/app/audio/notify-complete.mp3"

        Should -Invoke Invoke-MediaPlayer -Times 0 -Exactly
    }

    It "plays audio when lock file is older than 5 seconds (PS-02)" {
        $lockFile = Join-Path $env:NOTIFY_LOCK_DIR "claude-notify-complete.lock"
        Set-Content -Path $lockFile -Value "old" -NoNewline

        # Set mtime to 10 seconds ago
        (Get-Item $lockFile).LastWriteTime = (Get-Date).AddSeconds(-10)

        Mock Invoke-MediaPlayer {}

        . /app/scripts/notify-play.ps1 -Type "complete" -AudioFile "/app/audio/notify-complete.mp3"

        Should -Invoke Invoke-MediaPlayer -Times 1 -Exactly
    }

    It "mocks MediaPlayer without real audio hardware (PS-03)" {
        # No lock file -- cooldown passes immediately
        Mock Invoke-MediaPlayer {}

        . /app/scripts/notify-play.ps1 -Type "error" -AudioFile "/app/audio/notify-error.mp3"

        # Verify the mock was called with the correct AudioFile parameter
        Should -Invoke Invoke-MediaPlayer -Times 1 -Exactly -ParameterFilter {
            $AudioFile -like "*notify-error.mp3*"
        }
    }

    It "always exits 0 even when playback fails (PS-04)" {
        # PS-04 MUST use child process invocation (not dot-source)
        # because we're testing the script's exit code behavior
        # Use pwsh -File which runs in a child process
        $result = pwsh -File /app/scripts/notify-play.ps1 -Type "complete" -AudioFile "/nonexistent/file.mp3" 2>&1
        $LASTEXITCODE | Should -Be 0
    }
}
```

**Key considerations:**

- PS-01~03: Dot-source the script with Mock defined. The `return` statements (from Task 1 refactor) ensure `exit` does not kill the Pester session.
- PS-04: MUST use child process (`pwsh -File`) to test actual exit code. Dot-sourcing would use `return` which doesn't set `$LASTEXITCODE`. In the child process, the PresentationCore assembly load will fail (Alpine has no PresentationCore), but the catch block swallows the error and the script exits 0.
- D-06: Each test creates its own temp lock directory. AfterEach cleans up.
- The `. /app/scripts/notify-play.ps1 -Type "..." -AudioFile "..."` dot-source syntax passes params to the param() block. This works in PowerShell 7.
- The Mock must be defined BEFORE the dot-source call, because Pester Mocks are installed in the current scope and intercept calls made after their definition.

**Edge case for PS-04:** In the Docker Alpine container, `Add-Type -AssemblyName PresentationCore` will throw because the assembly doesn't exist. The catch block in notify-play.ps1 catches this and continues to the final `return`. Since `pwsh -File` runs the script, and the script reaches `return` at the end (not `exit`), the child process exits with code 0. Actually, `return` in a script invoked via `pwsh -File` sets `$LASTEXITCODE` to 0. But wait -- the `Add-Type` error happens inside `Invoke-MediaPlayer` which is inside the try block. The catch block catches it. Then the script continues to the final `return`. So `$LASTEXITCODE` should be 0. This is correct.

BUT: There's a subtlety. When `Invoke-MediaPlayer` is called with a nonexistent file, the `Add-Type` will still throw first (before even reaching the file check). The catch block catches it. The script returns 0. So PS-04 passes. BUT if Add-Type somehow succeeds (it won't on Alpine), the file-open would fail. Either way, catch handles it.

Actually, for PS-04 to work robustly, the Mock approach won't work in child process mode. The test needs to verify that the SCRIPT ITSELF exits 0. With `pwsh -File`, the script runs fresh in a child process where no Mock is active. So `Invoke-MediaPlayer` will actually try to run, fail (no PresentationCore on Alpine), and the catch block handles it. The final `return` gives exit code 0. This is the correct test for PS-04 -- testing the real error handling path.
